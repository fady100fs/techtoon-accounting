# 🔧 إصلاح عاجل — تضارب ترقيم الفواتير (INV-000001 already exists)

## المشكلة
عند حفظ فاتورة يظهر:
```
psycopg.errors.UniqueViolation: duplicate key value violates unique constraint
"invoices_invoice_number_key" — Key (invoice_number)=(INV-000001) already exists.
```

## السبب
- قاعدة البيانات تمنع تكرار رقم الفاتورة **عالمياً** (بيع + شراء معاً)
- صفحة الفواتير كانت تحسب الرقم التالي **لكل نوع على حدة** — فأول فاتورة
  شراء بعد فاتورة بيع INV-000001 تقترح الرقم INV-000001 نفسه → انهيار
- احتياطي الترقيم في services كان count()+1 وهو خاطئ بعد حذف أي فاتورة

## طريقة التنفيذ (VS Code Terminal)

1. انقل ملف `apply_hotfix_numbering.py` إلى مجلد البرنامج:
```
D:\PROG\Accounting Prog\Techtoon Accounting
```

2. في الطرفية:
```
cd "D:\PROG\Accounting Prog\Techtoon Accounting"
python apply_hotfix_numbering.py
```

3. أغلق نافذة البرنامج تماماً ثم شغّل `Techtoon.bat` من جديد.

> السكربت يأخذ نسخة احتياطية تلقائية إلى `backups/numbering_hotfix_<وقت>/`
> ويمكن تشغيله أكثر من مرة بأمان.

### بديل (نسخ يدوي)
انسخ الملفين من مجلد `fixed_files/`:
- `services.py` → مجلد البرنامج
- `invoice_page_common.py` → مجلد البرنامج

(استخدم هذا البديل فقط إذا فشل السكربت — الملفان مبنيان على النسخة
المحدثة سابقاً نفسها التي لديك)

## ما الذي يتغير؟
| قبل | بعد |
|-----|-----|
| الرقم المقترح لكل نوع على حدة | رقم فريد عالمياً (بيع+شراء) مطابق لقيد القاعدة |
| تعارض الرقم = انهيار بالخطأ | الرفع التلقائي لأول رقم حر وحفظ الفاتورة |
| count()+1 بعد حذف فواتير يقترح أرقاماً موجودة | أكبر رقم موجود + 1 (لا فجوات زائفة) |
| رسالة النجاح قد تعرض رقماً غير المحفوظ فعلياً | تعرض الرقم النهائي الفعلي |

## ما الذي لا يتغير؟
- الفواتير القديمة وأرقامها وقيودها — **لا تُمس إطلاقاً**
- النسق والواجهة — بلا أي تغيير بصري
- تواريخ الفواتير، الأسطر، المخزون، الدفعات
