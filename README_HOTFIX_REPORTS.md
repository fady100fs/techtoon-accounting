# 🔧 إصلاح دقة التقارير المالية + ظهور الأصناف — Techtoon Accounting

## ما المشكلة التي تعالجها هذه الحزمة؟

### 1) تقرير الأرباح والخسائر يعرض رقماً غير منطقي (مثال: 45,819 بدل ~4,000)
**السبب الجذري الذي تم اكتشافه في الكود:**
النسخ القديمة من البرنامج كانت تنشئ **قيد الفاتورة المحاسبي داخل حلقة أسطر الفاتورة** —
أي قيد كامل بمبلغ الفاتورة الكامل **لكل سطر**. فاتورة بيع من 10 أسطر تسجّل الإيراد 10 مرات!
- صفحة «التقارير > تقرير الأرباح والخسائر» تحسب الإيراد من **القيود المحاسبية** → متضخم
- «تقرير المنتج» يحسب من **الفواتير نفسها** → الرقم الصحيح
- «الميزانية» تتأثر بنفس التضخم (أرصدة العملاء/الموردين/المخزون مضخمة بالقيود المكررة)
- إضافة لذلك: الأرباح المحتجزة في الميزانية لم تكن تخصم تكلفة المبيعات/الرواتب/الإهلاك،
  وكانت الحسابات ذات الرصيد السالب تُحذف من العرض كلياً

### 2) الأصناف المدخلة لا تظهر في صفحة الأصناف، ولوحة التحكم كلها أصفار — رغم ظهورها في الفواتير
**السبب الجذري:**
صفحة الأصناف (ولوحة التحكم) تقرأ من **المرآة SQLite المحلية** التي كانت فارغة تماماً،
بينما صفحة الفواتير تقرأ مباشرة من **قاعدة البيانات المحلية (PostgreSQL)** التي تحتوي بياناتك.
+ أخطاء المزامنة كانت تُبتلع بصمت تام دون أي سجل.

## 📦 محتويات الحزمة

| الملف | وظيفته |
|---|---|
| `apply_hotfix_reports.py` | باتش الكود: قراءة مباشرة من قاعدتك المحلية + منع تكرار القيود مستقبلاً + إصلاح الميزانية + سجل مزامنة |
| `fix_journal_duplicates.py` | تنظيف القيود المكررة **التاريخية** (السبب الحقيقي لرقم 45,819) |
| `verify_reports.py` | فحص سريع يقارن إيراد القيود بإيراد الفواتير للتأكد من السلامة |

## 🚀 خطوات التنفيذ (VS Code Terminal — بالترتيب)

انسخ الملفات الثلاثة إلى مجلد البرنامج:

```
D:\PROG\Accounting Prog\Techtoon Accounting\
```

ثم نفّذ بالترتيب:

### الخطوة 1 — تطبيق باتش الكود
```bat
cd "D:\PROG\Accounting Prog\Techtoon Accounting"
python apply_hotfix_reports.py
```
- يأخذ نسخة احتياطية تلقائية إلى `backups\reports_hotfix_<وقت>\`
- يتحقق من سلامة الملفات بعد التعديل تلقائياً

### الخطوة 2 — تنظيف القيود المكررة التاريخية (هذه تُصلح رقم 45,819)
```bat
python fix_journal_duplicates.py
```
- أولاً سي**عرض** لك الإيراد قبل/بعد وعدد القيود المكررة المكتشفة
- يأخذ نسخة احتياطية JSON كاملة لجدولي القيود قبل أي حذف
- يطلب منك كتابة **نعم** قبل الحذف
- يحذف فقط النسخ **المطابقة تاماً** ويحتفظ بأول قيد لكل فاتورة
- 💡 لو أردت رؤية النتيجة دون أي تغيير: `python fix_journal_duplicates.py --dry-run`

### الخطوة 3 — التحقق
```bat
python verify_reports.py
```
- لو ظهرت «الإيرادات متطابقة» → التقرير المالي أصبح سليماً

### الخطوة 4 — إعادة تشغيل البرنامج
1. أغلق نافذة البرنامج تماماً
2. شغّل `Techtoon.bat` من جديد

## ✅ النتائج المتوقعة بعد التنفيذ

- **تقرير الأرباح والخسائر**: يطابق مجموع مبيعاتك الحقيقية (تقرير المنتج)
- **الميزانية**: أرصدة عملاء/موردين/مخزون حقيقية + أرباح محتجزة صحيحة
  (الإيراد − تكلفة المبيعات − المصروفات − الرواتب − الإهلاك)
- **صفحة الأصناف**: تُظهر كل أصنافك فوراً (قراءة مباشرة من قاعدتك المحلية)
- **لوحة التحكم**: الأرقام تعمل بدل الأصفار
- **الأداء**: أسرع بوضوح بعد كل فاتورة/دفعة (توقفت مزامنة المرآة غير اللازمة)
- **الفواتير الجديدة**: تُرحَّل بقيد واحد فقط مهما كان عدد الأسطر — المشكلة لن تعود
- أي خطأ مزامنة مستقبلي يُسجَّل في `data\sync.log` بدل أن يبقى صامتاً

## 🛡 ملاحظات أمان

- الفواتير وبنودها ومدفوعاتها **لا تُمس إطلاقاً** — التنظيف يخص القيود المحاسبية فقط
- نسختان احتياطيتان تلقائيتان: كود (`backups\reports_hotfix_*`) وبيانات (`backups\journals_backup_*` مع ملف JSON كامل قابل للاستعادة)
- السكربتات تعمل بأمان أكثر من مرة (التشغيل الثاني يتخطى ما طُبّق)
- لو كان عندك قيود «غير مطابقة تاماً» سيعرضها السكربت كبنود «مراجعة يدوية» ولا يحذفها

## ❓ إذا ظهر رقم متبقٍ بعد التنظيف

شغّل `verify_reports.py` وأرسل المخرجات مع مخرجات `fix_journal_duplicates.py` —
أشهر حالتين: (1) قيود بفوارق طفيفة تحتاج مراجعة يدوية (معروضة بالأسماء)،
(2) فواتير ملغاة بقويد قديمة — يمكن معالجتها بخطوة إضافية عند الطلب.
